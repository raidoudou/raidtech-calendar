# Raidtech Calendar

Raidtech Calendar is a self-hosted calendar for upcoming movie releases and TV episodes associated with requests in Seerr (or Jellyseerr). It can also include movies and series already present in a Jellyfin library.

The application uses Seerr's API to retrieve requests and metadata, optionally reads the Jellyfin library, and stores upcoming events and metadata caches in SQLite.

## Features

- Calendar view for upcoming movie releases and TV episodes.
- French-language metadata from TMDB through Seerr.
- Optional Jellyfin library synchronization.
- SQLite persistence for events and metadata caches.
- Incremental media synchronization to avoid reprocessing unchanged entries on every run.
- Retains previously cached metadata when an API request fails and a cached copy is available.
- Lightweight Flask application with a responsive web interface.

## Requirements

- Docker Engine
- Docker Compose v2
- A reachable Seerr or Jellyseerr instance and an API key
- Optional: a reachable Jellyfin instance and an API key

The application does not require TrueNAS. It can run on any host that supports Docker Compose.

## Quick start (Docker Compose)

1. Download or clone this repository.
2. Create your local environment file:

   ```bash
   cp .env.example .env
   ```

3. Edit `.env` and set at least:

   - `SEERR_URL`: base URL of your Seerr/Jellyseerr instance
   - `SEERR_API_KEY`: API key generated by Seerr/Jellyseerr

4. Optionally configure Jellyfin using `JELLYFIN_URL` and `JELLYFIN_API_KEY`.
5. Start the application:

   ```bash
   docker compose up -d --build
   ```

6. Open `http://YOUR_SERVER:30050`.

To inspect logs:

```bash
docker compose logs -f raidtech-calendar
```

To stop the application:

```bash
docker compose down
```

Your `.env` file and the `data/` directory are local and must not be committed to Git.

## Configuration

| Variable | Required | Default | Description |
|---|---:|---|---|
| `SEERR_URL` | Yes | none | Base URL of Seerr/Jellyseerr, without a trailing slash |
| `SEERR_API_KEY` | Yes | none | Seerr/Jellyseerr API key |
| `JELLYFIN_URL` | No | empty | Base URL of Jellyfin |
| `JELLYFIN_API_KEY` | No | empty | Jellyfin API key |
| `PORT` | No | `30050` | Host port exposed by Docker |
| `SYNC_SECONDS` | No | `3600` | Delay between synchronization cycles, minimum 300 seconds |
| `MEDIA_CACHE_HOURS` | No | `6` | Cache lifetime for media details and incremental sync freshness |
| `SEASON_CACHE_HOURS` | No | `24` | Cache lifetime for season episode data |
| `DB_PATH` | No | `/app/data/raidtech-calendar.sqlite3` | SQLite database path inside the container |
| `LOG_LEVEL` | No | `INFO` | Python logging level |

When Jellyfin is not configured, the application uses Seerr requests only.

## Persistent data and backups

Docker Compose mounts `./data` to `/app/data`. The SQLite database is stored there and survives container recreation.

Back up the `data/` directory regularly. Stop the container or use a SQLite-aware backup method when making a file-level copy of a live database.

## Reverse proxy and Jellyfin

You can publish the web interface through your preferred reverse proxy. Configure the proxy to forward to the host and port where Raidtech Calendar is exposed.

To display the calendar inside Jellyfin, use a compatible custom-tabs plugin and point the tab to the calendar's externally reachable URL. Reverse-proxy and authentication configuration depend on your own environment.

Do not expose the application publicly without considering access control. The application itself does not currently implement user authentication.

## Health endpoint

The application provides:

```text
GET /health
```

It returns a small JSON response indicating whether the service is running, whether the Seerr key is configured, and whether the database file exists.

## Synchronization behavior

The current implementation runs a synchronization cycle every `SYNC_SECONDS` seconds (default: one hour). Media that has not changed and was synchronized recently can be skipped. TMDB metadata and season data are cached separately.

This version does **not** yet implement separate independent schedules for new-media discovery, episode verification, and TMDB refresh. Those are potential future improvements, not current configuration options.

## Troubleshooting

- **No events appear:** check that `SEERR_URL` and `SEERR_API_KEY` are correct, then inspect the container logs.
- **Jellyfin items are missing:** verify the Jellyfin URL, API key, and that the media have TMDB provider IDs.
- **The application cannot reach Seerr/Jellyfin:** ensure the container can resolve and reach those services. When using Docker, service names on a shared Docker network can be used instead of host-specific IP addresses.
- **Old metadata remains visible:** the app may be using cached metadata after an upstream API request fails.

## Development

Install dependencies in a virtual environment:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Set the required environment variables, then run:

```bash
python app.py
```

The development server listens on port `30050`.
